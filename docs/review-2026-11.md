## 1. Как проводилось ревью

README на обоих языках, `docs/*`, `CHANGELOG.md`, `SECURITY.md`, `CONTRIBUTING.md`.

Окружение для запусков: Windows 11, WSL2, Ubuntu 26.04, bash 5.3.9, OpenSSL 3.5.5,
Python 3.14.4 и 3.9.24, ShellCheck 0.11.0 и 0.8.0. Все запуски шли **без root** на машине
без почтового стека. Настоящий почтовый сервер не использовался.

Метод подтверждения:

- для Bash-скрипта команды подменялись экспортированными bash-функциями (`export -f`).
  В дочернем `bash` функции имеют приоритет над поиском в PATH, а PATH скрипт задаёт сам.
  Ограничение: команды, вызванные через `timeout`, так не перехватываются;
- `lib/mail_stats.py` запускался на синтетических строках журнала с доменами `.example`
  и адресами из документационных диапазонов;
- скрипты экспериментов лежат в [`docs/review-2026-11/`](review-2026-11/), их можно повторить.

Существующие проверки на `33f2d51`: `bash -n`, `py_compile`, `tests/smoke.sh`,
`tests/mail_stats.sh`, `tests/full_json.sh` проходят, ShellCheck 0.11.0 без замечаний.

## 6. Можно ли покрыть текущую структуру тестами

Около 1000 строк логики проверок выполняются на верхнем уровне скрипта и вызывают внешние
команды напрямую. PATH зафиксирован, поэтому подмена утилит в тестах требует root, chroot или
контейнера с поддельными бинарниками в `/usr/sbin`. Перехват через `export -f` из раздела 1
работает только для команд, вызванных по имени без `timeout`, и не подходит как основа набора
тестов. Функции, которые можно протестировать отдельно, это парсеры аргументов и `mail_stats.py`.
Всё остальное зависит от глобального состояния (`MTA`, `MAIL_PLATFORM`, `TMPROOT`, счётчики).
Статусов UNKNOWN и N/A в модели нет: `pass`, `info`, `warn` и `critical` пишутся сразу в вывод
и в TSV.

Вывод: текущую структуру нельзя покрыть тестами без подмены всей системы. Это условие из
задания для переписывания; решение зафиксировано в [ADR 0001](adr/0001-architecture.md).

| README | «Missing optional tools are reported» | отсутствие `dig` даёт WARN, отсутствие `ss` даёт WARN, отсутствие `sshd -T` даёт OK (R-04) |

## 8. Пересечение с miab-radar

`miab-radar` в `main` сейчас один Bash-скрипт (`miab-radar`, `install.sh`) без Python-пакета.
Разбора доставки отдельных писем в mail-sec-audit нет. Здесь есть только агрегатная статистика
по Queue ID и топы, это допустимо. DNSBL-проверок (SORBS, коды Spamhaus 127.255.255.252/.254/.255)
в mail-sec-audit нет. Это вопрос доставляемости, он относится к miab-radar, поэтому здесь не
добавлялся. Для miab-radar: MIAB сам вызывает `reject_rbl_client zen.spamhaus.org=127.0.0.[2..11]`,
то есть коды ошибок публичных зеркал (127.255.255.x) уже отфильтрованы самим MIAB. Собственные
DNSBL-запросы miab-radar должны разбирать rcode и коды 127.255.255.252/254/255 отдельно.

## 9. Штатные конфигурации стеков (сверено с исходниками)

- **Mail-in-a-Box** (`setup/mail-postfix.sh`, `setup/mail-dovecot.sh`): `reject_unauth_destination`
  находится в `smtpd_relay_restrictions`, а не в recipient. Dovecot пишет в `/var/log/mail.log`
  напрямую (`log_path`), без hostname. `quota-status` слушает 12340 на всех адресах и закрыт ufw.
  `smtpd_tls_protocols` разрешает TLS 1.0 на 25 для оппортунистического TLS, mandatory-протоколы
  исключают TLS 1.0/1.1. Локальная доставка идёт через LMTP на `127.0.0.1:10025` (spampd).
  Обёртка `/usr/local/bin/mailinabox` состоит из `cd <checkout>; source setup/start.sh`, релизные теги annotated.
- **Mailcow** (`data/conf/postfix/master.cf`, `main.cf`, `docker-compose.yml`): порт 25 обслуживает
  postscreen → `smtpd pass`. `smtpd_relay_restrictions = permit_mynetworks, permit_sasl_authenticated,
  defer_unauth_destination`. syslog_name: `postfix/*`, `haproxy`, `enforced-tls-smtp`, `watchdog`.
  Опубликованные порты: 25, 465, 587, 143, 993, 110, 995, 4190, 80, 443; SQL, Redis и doveadm
  на `127.0.0.1`. `mailcow.conf` содержит пароли и не читается.
- **iRedMail** (`conf/dovecot`, `conf/amavisd`, `conf/iredapd`): Dovecot пишет в `/var/log/dovecot/*.log`,
  iRedAPD в `/var/log/iredapd/iredapd.log`. amavisd принимает на 10024/10026, повторная отправка
  на 10025. Это loopback-переход (R-16).

Настоящих шаблонов строк (`tests/fixtures/shapes/<stack>/`) в репозитории нет, поэтому все
форматы журналов в новых fixtures помечены как предположение.

Ограничения, которые остались:

- Форматы строк журналов в fixtures построены по документации и исходникам
  стеков. Реальных образцов (`tests/fixtures/shapes/<stack>/`) нет, поэтому
  разбор журналов на живых серверах MIAB, Mailcow и iRedMail не проверен.
- Аудит не запускался на реальном почтовом сервере. Полный прогон шёл только
  в WSL2 без root и на runner GitHub Actions (не почтовые хосты).
- Exim, OpenSMTPD и Sendmail поддерживаются на прежнем уровне: службы,
  эвристика relay, очередь. Статистики почты и разбора их журналов нет.
- Проверка relay локальная. Отсутствие open relay доказывает только внешний тест.
- Доверие к цепочке сертификатов не проверяется: только срок, имя и протокол.
- mypy 2.x проверяет с `python_version = 3.10`. Совместимость с 3.9 обеспечивают
  ruff (`target-version = py39`), `ast.parse(feature_version=(3, 9))` и CI на 3.9.

Что нужно соседним проектам:

- **miab-radar**: DNSBL-проверки должны разбирать rcode и отдельно коды
  127.255.255.252/254/255 публичных зеркал Spamhaus; SORBS закрыт. Для разбора
  `mail.log` можно перенести `logs/timeparse.py`, `logs/lines.py` и
  `logs/postfix.py`: структурный разбор полей защищает от враждебных адресов.
- **FleetOps**: `--format json` проходит контракт полей `HealthResult` и
  `CheckResult`. Статус N/A и INFO отображается в `ok`, исходный статус лежит в
  `metrics.native_status`. Если FleetOps нужен отдельный статус «неприменимо»,
  его нужно добавить в `fleetops/domain/statuses.py`.
